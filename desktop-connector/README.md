# RokidHub Desktop Connector

Windows-клиент с исходящим HTTPS polling: получает только свои RokidHub jobs и
запускает локальный `codex app-server` по stdio. Он не открывает входящий порт.

## Границы MVP

- raw bearer token хранится отдельным DPAPI blob текущего пользователя Windows;
- разрешённые папки и соответствие conversation/thread хранятся только локально;
- профиль доступа выбирается только локально; сеть всегда выключена, а доступ
  не выходит за выбранную разрешённую папку;
- Hub получает статусы и короткий итог, но не raw agent delta, патчи или файлы;
- Hub получает короткое голосовое имя активного проекта для HUD, но никогда не
  получает абсолютный путь или список разрешённых папок;
- `--mock` проверяет полный Hub round trip, не запуская Codex и не читая файлы.

## Установка

```powershell
cd L:\pythonProject\RokidGlasses\rokidhub-desktop-connector
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

После установки можно открыть единое окно настройки:

```powershell
.\start-gui.ps1
```

GUI использует современную тёмную оболочку RokidHub с отдельными разделами
«Обзор», «Проекты», «Codex», «Безопасность», «Активность» и «Настройки».
Все интерфейсные значки используют единый монохромный Font Awesome 4.0.3;
цветные системные иконки Windows не смешиваются с дизайном. Шрифт и его
лицензионная заметка упакованы внутрь Connector, интернет для отрисовки не нужен.
В нём доступны привязка ПК, выбор разрешённых папок, проверка соединения,
mock/real запуск, локальный журнал, модель, глубина анализа и поддерживаемый
моделью режим скорости.
На «Обзоре» отдельно показаны состояния привязки ПК и Codex-плагина в очках.
Карточка ПК открывает «Настройки», а карточка очков — кабинет RokidHub; подробная
подсказка при наведении объясняет установку APK через Nexus, разрешения
STT/HUD/TTS и ввод одноразового кода. До привязки ПК статус очков намеренно не
угадывается: только авторизованный ПК может запросить у Hub состояние устройств
того же пользователя.
На странице «Проекты» radio-кнопкой отмечается папка по умолчанию. Она становится
`cwd` новой задачи, если для диалога проект ещё не выбран голосом; порядок папок
при этом не меняется.
Кнопка «Обновить список» получает модели и поддерживаемые уровни напрямую от
установленного `codex app-server` методом `model/list`, поэтому список не
зашит в Connector.

Крестик не завершает Connector: окно скрывается в системный трей. Через меню
иконки можно открыть окно, запустить или остановить Connector, включить
автозагрузку, выбрать язык и выполнить настоящий выход. При выходе завершается
только дочерний процесс этого Connector.

Язык интерфейса по умолчанию определяется по языку Windows. В настройках и в
меню трея можно явно выбрать `Русский`, `English` или снова включить
автоматический режим. Выбор хранится только в локальном `config.json`; на Hub
он не отправляется. Локальные окна подтверждения Codex используют тот же язык.
Дочерний CLI всегда запускается с UTF-8 stdout/stderr; GUI декодирует поток
инкрементально, поэтому русские строки и символы, разделённые между QProcess
chunks, не превращаются в `�` в разделе «Активность».

Автозагрузка выключена по умолчанию. Если пользователь явно включает её в GUI,
Connector создаёт только значение текущего пользователя в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. В команду автозагрузки
не попадают токены; окно стартует свёрнутым и запускает исходящий polling loop.

## Доступ и голосовой выбор проекта

Профиль доступа выбирается только локально в GUI:

- `Только анализ` — `readOnly`, без запросов на запись;
- `Запрашивать изменения` — по умолчанию `readOnly`, запрос App Server
  подтверждается отдельным окном Windows;
- `Полный доступ к выбранному проекту` — `workspaceWrite` только для выбранной
  разрешённой папки, без сети и без полного доступа к ПК.

`dangerFullAccess` намеренно не включён в голосовой Connector. Повышение доступа
нельзя выполнить командой с очков. Любой запрос App Server за пределами выбранной
папки отклоняется до показа окна подтверждения.

Для каждой разрешённой папки кнопкой `Голосовое имя…` можно задать короткое имя.
После этого скажи в очках: `выбери проект Рокид`. Hub маршрутизирует команду, но
абсолютные пути, список папок и соответствие `conversation_id` → папка остаются
только в локальном `config.json`.

Голосовой выбор относится к текущему диалогу и имеет приоритет над отмеченной
папкой по умолчанию. Для нового диалога без такого выбора Connector использует
локальное поле `default_root`.

Сначала явно выбери хотя бы одну папку. Для старой конфигурации без `default_root`
Connector совместимо использует первый путь, после чего выбор можно изменить в GUI:

```powershell
.\start.ps1 configure --allow-root L:\pythonProject\RokidGlasses
```

Если Hub запущен локально:

```powershell
.\.venv\Scripts\rokidhub-connector.exe configure `
  --hub-url http://127.0.0.1:8000 `
  --allow-root L:\pythonProject\RokidGlasses
```

## Привязка

В GUI открой «Настройки» и нажми «Привязать ПК». Если основной polling уже
запущен (в том числе автозагрузкой), окно само корректно остановит его и начнёт
привязку. Одноразовый код показывается прямо в «Настройках» с кнопкой
«Скопировать», а также остаётся в локальном журнале «Активность».

```powershell
.\start.ps1 pair
```

Connector покажет одноразовый код. Войди в кабинет RokidHub, введи код в секции
`RokidHub · Codex` и вернись в консоль. Никакая авторизация Codex в этом шаге не
запрашивается и не передаётся Hub.

## Проверка и запуск

```powershell
.\start.ps1 doctor
.\start.ps1 models
.\start.ps1 run -Mock
.\start.ps1 run
```

`doctor` проверяет DPAPI token, разрешённую папку, доступность Hub и наличие
команды `codex`, но не запускает Codex turn.

Выбранные `model`, `reasoning_effort` и `service_tier` хранятся только в
локальном `config.json` и передаются как поля `model`, `effort` и
`serviceTier` в `turn/start`.
Профиль доступа определяет `sandboxPolicy` и `approvalPolicy`, но сеть остаётся
выключенной, а `dangerFullAccess` не используется.

Конфигурация находится в
`%LOCALAPPDATA%\RokidHub\DesktopConnector\config.json`, DPAPI blob — рядом в
`connector-token.dpapi`. Не копируй blob на другой ПК или в репозиторий.
